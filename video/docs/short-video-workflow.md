# ショート動画制作フロー

最終更新日: 2026-08-16

公開済みSEO記事を正本に、45秒前後の縦動画を半自動で作るための標準手順です。映像の自動生成は補助であり、内容、匿名化、音量、ライセンス、公開判断は人が確認します。

## 標準仕様

| 項目 | 初期値 |
| --- | --- |
| 画面 | 1080 × 1920、9:16 |
| フレームレート | 30 fps |
| 長さ | 40〜50秒 |
| 構成 | 問い → 結論 → 要点1 → 要点2 → 意味 → CTA |
| ナレーション | 音量1.0、開始12フレーム（0.4秒） |
| BGM | 音量0.28、30フレームでフェードイン、75フレームでフェードアウト |
| 出力 | H.264 MP4、CRF 18 |

BGM 0.28は1本目で採用した初期値です。曲の密度やボーカルの有無で聴感が変わるため、固定の正解とはせず、スマートフォンとイヤホンの両方で確認します。

## 1. 元記事を決める

- 公開済みで、出典と確認日が揃った記事を選ぶ
- 1本の動画では1つの疑問だけを扱う
- `sourceSlug` と画面に出す記事名を決める
- EXP記事は `.private/` の公開承認と匿名化を再確認する

## 2. 台本を作る

ナレーションは40〜48秒を目安にし、次の順番で短くします。

1. 0〜6秒: 検索者が持つ疑問
2. 6〜12秒: 先に結論
3. 12〜26秒: 重要な違いを2点
4. 26〜35秒: 実務でどう使われるか
5. 35〜41秒: なぜ重要か
6. 41〜47秒: 記事へのCTA

記事本文を読み上げるのではなく、耳で一度で理解できる文へ言い換えます。年収、企業情報、採用情報など更新性の高い内容は、収録前に元記事の出典と確認日を見直します。

## 3. マニフェストを作る

`video/manifests/_template.ts` を複製し、動画ID、元記事、画面文言、音声、確認日、公開状態を記録します。

```text
video/manifests/short-002-example.ts
video/public/audio/narration-short-002.m4a
video/public/audio/common/shining-leon-albertson.mp3
```

元の録音名や個人を特定し得る名前は使いません。作品固有のナレーションは `public/audio/`、今後も使うBGMは `public/audio/common/` に置きます。どちらもGit管理外です。

## 4. 音声を整える

- ナレーションは冒頭と末尾の不要部分を切り、声量を揃える
- BGMは動画尺より少し長く切り出す
- 収録音声はAAC 48kHz、BGMはMP3またはAAC 48kHzを基本にする
- 曲名、制作者、入手元、ライセンス、帰属表示の要否を確認する

YouTubeオーディオライブラリで「帰属表示が必要」と示された曲は、生成したクレジット文を動画説明欄へそのまま掲載します。確認前はマニフェストを `confirmation-required` のままにします。

標準BGMの `Shining / Leon Albertson feat. Adryon de León` は、YouTubeオーディオライブラリの帰属表示不要曲として2026-08-16に確認済みです。別の曲へ変更した場合は、曲ごとに利用条件を確認し直します。

## 5. 映像を同期する

ナレーションの無音区間を場面転換の基準にします。秒数からフレームへ変換する時は `秒数 × 30` とし、前後の場面を約12フレーム重ねて自然にクロスフェードさせます。

- 共通の音声処理は `src/components/AudioTracks.tsx`
- 共通の上下枠は `src/components/Chrome.tsx`
- 作品固有の図解と場面は `src/compositions/`
- 尺とComposition登録は `src/root.tsx`

## 6. 生成して確認する

```bash
npm --prefix video run still
npm --prefix video run render
```

確認項目:

- 冒頭1秒で疑問が伝わる
- 字幕がスマートフォンで読める
- ナレーションがBGMより明瞭
- BGMが無音に感じられず、声も邪魔しない
- 音割れがない
- 元記事、確認日、CTAが正しい
- 公開不可情報や元音声のファイル名が露出していない

## 7. 公開して記録する

最初は限定公開でスマートフォン確認し、問題がなければ公開します。公開後はマニフェストを `published` にし、媒体と公開日を記録します。URLが分かる場合だけ `publication.url` を追加します。

公開後24時間、7日、28日を目安に、再生数だけでなく次を記録します。

- 視聴を継続した割合
- 平均視聴時間または視聴維持率
- 高評価、コメント
- プロフィールや記事への流入
- Career Compass開始など次の行動

制作ごとの結果と調整理由は `production-log.md` に追記します。
