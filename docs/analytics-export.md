# GA4・Search Console 日次エクスポート MVP

## 構成と事前条件

専用 Google スプレッドシートに紐づく Apps Script が、実行者の OAuth 権限で GA4 Data API と Search Console API を読み取り、同じファイルの6シートに日別の集計表を書きます。外部サービス、サービスアカウント、API キー、有料の製品は不要です。GA4 プロパティと GSC プロパティへの読み取り権限、シートの編集権限を持つ Google アカウントが必要です。Google の無料枠・各種クォータ内での利用を想定しますが、無料枠の範囲内での完了を保証するものではありません。

- `scripts/analytics-export/Code.gs`: スクリプト本体。Google の REST API を `UrlFetchApp` から呼びます。
- `scripts/analytics-export/appsscript.json`: 日本時間と OAuth スコープの設定。
- 1行は「日付 × 表の対象」。同じ日付・表を再取得すると、その日の行全体を置き換えます。ヘッダーや列を編集せず、分析用の数式やグラフは別シートに置いてください。
- 直近7日（昨日を含む）を毎日更新します。GSC は確定データのみで、日付別 API に出ない日は既存行を消さずに次回再確認します。日付が出ない理由は未確定またはデータなしであり、0と断定できません。
- 初回の過去90日は昨日を含む90日です。データの存在・保持期間、権限、API 側の制約によって取得可能な範囲は変わります。GSC の日付が出ない日はスキップします。直近7日より古い未確定日が後から確定した場合は、自動では補完されないため、再度 `startBackfill` を実行してください。
- 処理位置はスクリプトプロパティに保存し、約4分を目安に一時停止して1回限りのトリガーで続行します。取得失敗時は途中結果をその日・表には書かず停止し、実行ログで原因を確認後 `continueBackfill` を実行してください。次の日の日次実行でも再開します。シート書き込み自体はトランザクションではないため、中断した場合は同じ日を再取得して修復してください。

## Google 側の初期設定

1. GA4 の管理画面で対象サイトの**数値のプロパティ ID**を確認します。`G-` で始まる測定 ID ではありません。実行する Google アカウントに対象プロパティの閲覧権限を付けます。GA4 のプロパティのタイムゾーンも記録してください。
2. Search Console で対象サイトの所有権を確認し、同じアカウントにプロパティの閲覧権限を付けます。登録済みのプロパティ文字列をそのまま使います。URL プレフィックスなら `https://mfg-compass.com/`、ドメインプロパティなら `sc-domain:mfg-compass.com` です。登録状況に合わせて選択してください。
3. Google スプレッドシートを新規作成し、共有範囲を必要な人だけに限定します。URL の `/d/` と次の `/` の間がスプレッドシート ID です。Google Drive 連携で ChatGPT に参照させるときは、必要な範囲だけアクセスを許可してください。
4. スプレッドシートの「拡張機能」→「Apps Script」を開き、`Code.gs` に本リポジトリの同名ファイルの内容を貼り付けます。プロジェクトの設定でマニフェスト表示を有効にし、`appsscript.json` を同梱ファイルの内容に置き換えて保存します。Apps Script のタイムゾーンは `Asia/Tokyo` です。
5. [標準 Google Cloud プロジェクトへの切り替え](https://developers.google.com/apps-script/guides/cloud-platform-projects)を行い、そのプロジェクトの [API ライブラリ](https://console.cloud.google.com/apis/library) で **Google Analytics Data API** と **Google Search Console API** を有効にします。必要に応じて Google Auth Platform の OAuth 同意画面とテストユーザーを設定します。API を呼ぶだけなら Apps Script API や高度なサービスの有効化は不要です。組織の制限で利用できない場合は管理者に確認します。
6. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に次を設定します。値をコード、公開リポジトリ、スクリーンショットへ保存しないでください。

| キー | 値 |
| --- | --- |
| `GA4_PROPERTY_ID` | GA4 の数値プロパティ ID |
| `GSC_SITE_URL` | 登録済みの GSC プロパティ文字列 |
| `SPREADSHEET_ID` | 保存先スプレッドシート ID |

7. エディタで `setup` を選び実行し、表示される認可内容を確認して許可します。これは6シートの作成と、同じ実行者が所有する既存の `dailyExport` トリガーの置換を行います。異なるアカウントが設定したトリガーは削除できないため、運用者を1人に固定し、重複作成しないでください。Sheets の書き込み権限と、GA4/GSC の読み取り権限、外部通信、トリガー管理を要求します。認証情報やアクセストークンをコピーする必要はありません。未確認アプリ警告や組織のブロックが表示された場合は Google の案内と組織の方針に従ってください。
8. `startBackfill` を手動実行します。自動継続で完了まで進みます。Apps Script の「実行数」とログで `Backfill completed.` またはエラーを確認します。シートに90日分が実際に存在するか、GA4 と GSC の画面で代表日・ページの定義を揃えて照合します。行がない日は0とみなさないでください。
9. トリガー画面で `dailyExport` の時間主導型トリガーを確認します。毎日日本時間6時台の実行を指定しますが、Google により時刻は分単位で前後します。翌日以降の実行履歴とシート更新を確認して運用開始としてください。トリガーは作成者の権限で実行されます。認可・アクセス変更後は `setup` 等を手動実行して再認可してください。

## 表と集計の定義

| シート | 粒度 | 主な列 |
| --- | --- | --- |
| `GA4_Daily` | 日付 | アクティブユーザー、セッション、表示回数 |
| `GA4_Pages` | 日付 × パス | 表示回数、アクティブユーザー |
| `GA4_Events` | 日付 × イベント名 × 7つのカスタムパラメータ | イベント数、総ユーザー数 |
| `GSC_Daily` | 日付、サイト単位 | Google ウェブ検索のクリック、表示、CTR、平均掲載順位 |
| `GSC_Pages` | 日付 × URL | Google ウェブ検索のクリック、表示、CTR、平均掲載順位 |
| `GSC_Queries` | 日付 × 検索語、サイト単位 | Google ウェブ検索のクリック、表示、CTR、平均掲載順位 |

日付は `YYYY-MM-DD` の文字列です。GA4 の日付は **GA4 プロパティのタイムゾーン**、GSC の日付は **米国太平洋時間**、実行時刻は **日本時間**です。日付が同じでも集計区間は一致しません。GSC は `type=web` のみで Discover、ニュース、画像などは含みません。GA4 はプロパティ全体・全流入経路であり、自然検索に限定されません。プロパティに複数サイトやアプリが含まれる場合、それらも集計され、パスが同じサイトはまとまります。この場合は専用プロパティを使うか、実装を変更してから運用してください。

`GA4_Events` はイベント名が `career_compass_` で始まるもの、`career_agents_cta_click`、`affiliate_outbound_click` に限ります。`source_page`、`cta_location`、`cta_variant`、`step_number`、`result_type`、`destination_group`、`agent_id` のイベントスコープのカスタムディメンションを使います。事前に GA4 で登録し、Data API で利用できる状態にしてください。`total_users` は各行に該当するユニークユーザー数です。日やパラメータの異なる行を合算して期間全体の人数にはできません。未設定のパラメータは GA4 が返す値のまま出力されます。登録前の値が取得できるとは限らず、過去分を完全に復元できるとは限りません。新規登録の反映待ちなどで取得に失敗した場合、処理は停止するため、利用可能になってから再実行してください。

旧形式の `GA4_Events` がある場合、列順と列数が変わるため、そのまま更新するとヘッダー検証で停止します。既存データを残すため旧タブを別名に変更してからスクリプトを更新してください。次回実行で新しい `GA4_Events` が作成され、直近7日分が取得されます。過去分が必要なら既存バックフィルの完了後に `startBackfill` を実行します。旧タブの値を新しい列順に移し替えるだけでは `total_users` は復元できません。

GA4 の `screen_page_views` はページやアプリ画面の表示回数で、同じ人の再表示も含みます。`active_users` はその日・その行でのユニークユーザーです。日・ページをまたぐユーザー数を合計して期間やサイト全体のユニーク人数とは扱えません。ページ別の表示回数は入口ページや検索流入の数ではありません。GA4 の `page_path` はクエリ文字列を除き、GSC の `page_url` は完全な URL です。両者を比較する場合、ホスト・パス・URL パラメータ・canonical を確認してください。

GSC の `ctr` は割合（例 `0.05` = 5%）、`position` は平均掲載順位です。期間集計の CTR はクリック合計 ÷ 表示回数合計、順位は表示回数を重みにした平均で算出します。ページ集計は URL 単位、日次・クエリ集計はプロパティ単位なので合計が一致するとは限りません。GSC はプライバシー保護や API の制限により、クエリやページの詳細行をすべて返すとは限りません。GSC クリックは Google 検索結果からのクリック、GA4 セッションは計測されたセッションであり、同じ数にも加算対象にもなりません。計測漏れ、同意・広告ブロック、処理遅延なども差の原因です。

`GSC_Queries` や URL・パスには、検索語やサイト設計により個人情報や機密情報が含まれる可能性があります。取得結果は非公開で扱い、共有前に内容を確認し、不要なら該当シートを削除するだけでなくスクリプトから対象を外してください。集計表であっても匿名化が保証されるわけではありません。

## エラー、上限、運用

- 実行ログには行数・日付・表名・HTTP ステータスを記録し、API レスポンス本文、検索語、トークンは出力しません。429、500、503 は最大3回、短い指数バックオフで再試行します。それ以外や再試行後の失敗は停止します。403 は API 有効化、アカウント権限、GSC プロパティ文字列を確認し、429 はクォータの回復を待って再開します。トリガーの失敗通知と Apps Script 実行履歴も確認してください。
- GA4 は `rowCount` と offset、GSC は `startRow` によってページ送りします。1日・1表あたり **10,000行を超える場合は失敗**し、その日の既存データを維持します。必要に応じて `maxRowsPerReport` を調整できますが、実行時間、メモリ、スプレッドシートのセル数上限に注意してください。GSC 自体の上位行制限・非公開クエリ・クリック同数時のページング順の不安定さは解消できず、重複キーを検出した場合は停止します。重複がなくても API が返さなかった行は検出できません。GA4 のサンプリング・しきい値・`(other)` への集約が報告されたときは実行ログに警告します。
- Apps Script には1実行6分などの制限があり、実際の処理量によっては1日・1表の取得またはシート更新が時間内に完了しないことがあります。その場合は期間を分割するだけでは解決せず、取得対象や保存方式の見直しが必要です。日次の直近7日更新が4分以内に完了しない場合も、日次処理の分割が必要です。失敗した日次の更新は次回に直近7日分を再試行します。長期停止した場合は `startBackfill` で再取得してください。
- 更新はシート全体を読み直すため、蓄積量が増えると遅くなります。スプレッドシートのセル数・Apps Script の日次実行時間・API クォータを定期確認してください。容量や処理時間の限界に近づいたら年度別ファイル等への移行を検討します。シートには手編集や別スクリプトからの同時更新を行わないでください。
- 設定先の変更時は既存データが別プロパティと混ざらないよう新しいスプレッドシートと Apps Script プロジェクトを用意してください。GA4/GSC の権限やクォータは [GA4 Data API](https://developers.google.com/analytics/devguides/reporting/data/v1/quotas)、[GSC データ取得](https://developers.google.com/webmaster-tools/v1/how-tos/all-your-data)、[Apps Script クォータ](https://developers.google.com/apps-script/guides/services/quotas) と [時間主導トリガー](https://developers.google.com/apps-script/guides/triggers/installable) を参照してください。
