# SEO Strategy

最終更新日: 2026-09-26

## 役割

SEO は Career Compass だけへ送客するためのものではありません。検索意図にそのページで答えたうえで、次に必要な理解へ内部リンクします。

代表的な流れ:

```text
技術・業界の検索
  → ガイド / 業界地図 / 企業ページ
  → 関連工程・企業・職種
  → 必要なら Career Compass

転職・経験整理の検索
  → 実体験ガイド / Career Compass
  → 企業研究 / 職務経歴の整理
  → 必要なら相談準備・エージェント比較

製造技術・品質指標の検索
  → 解説記事 / 計算ツール
  → 操作して理解する学習体験
  → 実務で次に確認する項目 / 関連技術記事
```

すべての記事へ同じ CTA を置きません。検索意図を満たすことを優先します。

## 現行URL

- `/career-compass`: 現在地チェック
- `/industry-map`, `/segments/[slug]`: 業界構造
- `/companies`, `/companies/[slug]`: 企業研究と企業別キャリア準備
- `/compare`, `/compare/[slug]`: 企業比較
- `/guides`, `/guides/[slug]`: 技術・業界・キャリア記事
- `/rankings`, `/rankings/[slug]`: 基準時点のあるランキング
- `/semiconductor-watch`: 企業・地域・テーマを横断し、公式情報スナップショットから業界の変化を探索するダッシュボード
- `/career-agents`: エージェント比較
- `/career-consultation`: 相談準備

旧 `/companies/[slug]/career-prep` は、重複を避けるため `/companies/[slug]#career-prep` へ恒久リダイレクトします。canonical と sitemap の対象は親の企業詳細URLだけです。

存在しない `/diagnosis`、`/diagnosis/result`、`/agents`、`/english` をリンク設計へ使いません。新規URLを追加する前に、既存ページとの検索意図の境界を決めます。

`/semiconductor-watch` は半導体ニュース・市場動向を横断して探索するアプリを中心とし、公式シグナルでは企業・地域・テーマ・工程と原文の関係を主情報にする。業界構造を説明する `/industry-map`、基準日時点の数値を比較するランキング、勤務地を探す `/semiconductor-map` と検索意図を分ける。企業IR・規制提出・業界団体を手動確認した静的スナップショットであること、確認時刻、時価総額の基準日を本文で示し、「リアルタイム」「最新速報」を標榜しない。NewsArticle構造化データは自動収集・公開日時・訂正運用が整うまで追加しない。

### 全国拠点ハブ

`/semiconductor-map` は「日本の半導体企業・工場・研究拠点」を勤務地から探す検索意図に対応します。2026-09-05に全国ページをindex対象としてsitemapへ追加しました。パラメータ付きURLは `noindex, follow` とし、canonicalを全国URLへ統一します。

- V0は全国ページだけをindex対象にする
- パラメータ付きの絞り込み結果はindex対象にしない
- 企業名、正式拠点名、都道府県、市区町村、役割、確認日を初期HTMLへ出す
- 画面に表示しない求人状態を構造化データへ追加しない
- `/industry-map` の業界構造、`/companies` の会社単位一覧と検索意図を分ける
- 熊本を含む都道府県ページは、5拠点以上、複数企業、地域固有情報、検索需要を満たすまで作らない
- 2026-09-05に公開URLを対象としたDesktop Chrome・Pixel 7向けE2Eで、初期一覧、絞り込み、0件復帰、地域選択、canonical、noindex、JavaScriptなし表示を確認した

### 記事カテゴリ

`/guides/[slug]` の記事URLはカテゴリ変更時も維持し、記事データと `/guides` の内部リンクで次の4カテゴリを示します。

- 製造業DX・AI
- 半導体・製造技術
- 企業・業界研究
- キャリア・実体験

カテゴリの記事数と検索需要が十分になるまではカテゴリ別URLを増やさず、`/guides` 内のカテゴリ導線をハブとして使います。

### 分野別比較の主力候補（2026-09-20）

主力候補は既存の次の3記事とする。全体ランキングと検索意図を分け、数値の出典・対象範囲を保持したまま育てる。

| 記事slug | 中心の検索意図 | 比較しないもの |
| --- | --- | --- |
| `semiconductor-equipment-sales-ranking` | 装置メーカーの売上規模と対応工程 | 全社売上、工程別シェア、性能順位 |
| `memory-manufacturer-ranking` | DRAM・NANDそれぞれの売上シェア | SSD性能、DRAMとNANDを合算した順位 |
| `optical-semiconductor-manufacturers` | 光半導体メーカーの用途・製品例 | 出典が揃っていない総合順位、供給網全体の網羅 |

- 時価総額ランキングは世界TOP30の後に3記事の比較指標・対象期間を添えて案内する。関連記事だけに依存しない。
- 企業・業界記事一覧にも3記事を掲載。装置メーカー基礎記事から売上ランキングへ進める本文リンクを置き、基礎説明と順位比較の役割を分ける。
- Q&Aは本文で説明済みの比較範囲・制約を簡潔に回答する。本文とFAQPage構造化データは既存の共通データから生成し、検索結果への特別な表示を保証しない。
- 2026-09-20の更新は内部リンクと説明の整理。ランキング数値・製品データの確認日は更新していない。記事の更新日を市場データの基準日にしない。
- 本番反映日を起点に、14日後は各URLの登録状態、28日後は検索クエリ・表示・クリック・CTR・順位と内部遷移、56日後は継続傾向を確認する。反映日とGA4受信は別途確認する。
- 親記事からの遷移は既存 `article_internal_click` の `source_slug` / `destination_path`、企業への遷移は `article_company_click`、操作は既存の装置・メモリ・光半導体イベントを使う。閲覧と操作を同じ成果として足さない。
- 表示が少ない場合は登録状態と需要を先に確認する。表示はあるがクリックが少ない場合はクエリと本文・タイトルの一致を見る。流入後に関連遷移がない場合は記事の説明と導線を見直す。少数データから勝敗を決めない。
- 次の新規記事は、既存URLで満たせない検索意図と、公開可能な根拠が揃ったものに限る。検索語の表記違いだけで記事を増やさず、転職意図の強い実体験記事は取材工程を通す。

### キャリア

- 製造業経験を半導体職種へつなげる実体験
- 職務経歴書、英語、求人票、転職エージェント

### 製造技術の実務学習

- Cp・Cpk、Pp・Ppkの違いと計算
- 平均、ばらつき、規格幅、中心ずれの関係
- 管理状態と工程能力の違い
- 管理図、測定システム、歩留まり、OEEなどの関連指標
- 記事で概念を説明し、計算ツールで手元のデータを確認し、学習モードで因果関係を体験する

同じキーワードに記事、計算ツール、学習ページを重複させません。中心検索意図を次のように分けます。

- 「Cp Cpk 計算」「Cpk 計算ツール」: 実データ計算を主目的にする
- 「Cp Cpk 違い」「Cpk 1.33 意味」: 記事またはツール内解説で意味へ答える
- 「Cpk 平均 ずれ」「標準偏差 Cpk 変化」: 操作して理解する学習体験を中心にする

学習機能は重要な説明をJavaScript操作だけに閉じ込めません。初期状態、操作項目、変化の原則、注意点をHTML本文にも記載し、検索エンジンと操作できない利用者にも内容が伝わるようにします。

半導体製造工程シリーズの細かな検索意図の境界は `.private/semiconductor-process-seo-map.md` で管理します。

## 検索公開の標準（2026-09-22）

技術ツール・REFは必要な出典・数値・匿名化・動作確認の完了後、初回からindex可能で公開実装する。人間レビュー待ちを理由に定型のnoindex期間を設けない。canonical・構造化データ・sitemap・一覧と関連導線を同時に整える。人間試用と検索需要の評価は公開後に行い、既知の重大な問題や重要な未確認事項があれば先に修正・除外する。

重複URL・検索条件付きURL・未完成ページ・明示的な下書きのnoindexは維持する。既存draftの一括公開はしない。人間確認の有無や本番反映日を推測で記録しない。詳細は `AGENTS.md` の「公開の標準手順」に従う。

## ページ要件

- 1ページにつき中心検索意図を一つ決める
- title と description は本文で実際に答える内容に合わせる
- 著者、確認者、公開日、更新日、出典を表示する
- 変動情報は対象時点を明示する
- canonical を一つにする
- noindex ページを sitemap に含めない
- 重要な情報を画像だけに閉じ込めない
- 関連記事のアンカーは遷移先の内容が分かる表現にする

## 内部リンク

- ハブから詳細へ、詳細からハブ・前後テーマへ戻れるようにする
- 技術記事から、扱う装置・材料・企業・職種へつなぐ
- 企業ページから、事業セグメント、比較、同一ページ内のキャリア準備へつなぐ
- 実体験記事から、読者が次に必要とするガイドや Career Compass へつなぐ
- Career Compass の結果から、接点のある企業と相談準備へつなぐ
- 企業一覧と業界地図から `/semiconductor-map` へ、確認済み企業の詳細から該当する国内拠点へつなぐ
- `/semiconductor-map` から企業詳細、業界地図、Career Compassへ戻れるようにする
- CTA のためだけに本文と関係の薄いリンクを置かない
- 製造技術記事から対応する計算・学習ツールへ、ツールから詳しい定義・注意点の記事へ相互にリンクする
- 学習ツールの操作後は転職CTAを直接強調せず、管理図、測定システム、改善記録など次に必要な技術理解へつなぐ

## 構造化データ

ページ内容に応じて、次を使います。

- WebSite
- Organization
- Article
- BreadcrumbList
- FAQPage
- ItemList
- WebApplication

画面にない情報を構造化データへだけ追加しません。公開日・更新日・著者は本文表示と一致させます。

## sitemap と公開品質

- `src/app/sitemap.ts` を正本とする
- ガイドは公開状態と `updatedAt` を使う
- 企業詳細は個別キャリア情報があるページだけ含める
- 404、noindex、canonical、robots と sitemap を矛盾させない
- 新しい記事種別を追加した時は静的生成対象と発見経路を確認する

## 更新判断

### EFEM英語版の検索需要実験（2026-09-21）

- 対象は `/en/guides/semiconductor-wafer-handling-efem-manufacturers` の1本。中心検索意図は `what is an EFEM`。EFEMの構成・搬送フロー・代表メーカーの提供範囲を説明する。
- 一般英語向け `hreflang=en` と日本語 `ja` を日英双方へ設定し、各言語を自己参照canonicalにする。国別URLや自動言語転送は作らない。
- `status: draft` または翻訳確認日・公開日が未設定の場合はnoindex。公開条件を満たすとsitemap、日英hreflang、日本語からの言語リンクが有効になる。原文・翻訳の更新日、各出典の確認日は別々に扱う。
- 公開前に英語の専門用語、図表、提供範囲、公開禁止情報、リンク先言語をエージェントが確認する。人間レビューは一律の公開条件にしない。記事データの `reviewedBy` は確認担当者であり、`translation.reviewedAt` 未設定の段階で確認済みとして表示しない。
- 本番反映日を非公開の記事台帳に記録し、14日後にURL登録、28・56・84日後に確定済み日付までのクエリ・表示・クリックを確認する。未反映の間は確認日を設定しない。
- GSCは対象URL・ウェブ検索で集計し、国別は別内訳にする。英語のクエリを手動確認し、匿名化で取得できないクエリを推定しない。国から検索言語を決めつけない。
- GA4は対象ページをランディングページとするOrganic Searchセッションを主に確認する。GSCクリックとGAセッションは合算しない。英語URLの閲覧を海外閲覧と同一視しない。
- `article_language_switch` は固定の遷移元・遷移先パスと言語で補助計測する。英語の関連リンクには既存イベントへ `source_locale=en` と `source_page` を付ける。実験開始前に必要なカスタムディメンションの登録・受信を確認し、未登録の過去データを復元済みとしない。言語切り替えを獲得成果やキーイベントに加えない。
- 84日時点の確定済みデータで直近28日とその前28日の両期間に、想定した英語クエリからのクリックが確認できれば2本目を検討する。登録状態と需要を分けて評価し、未達・データ不足なら追加翻訳を保留する。予測や成功保証ではない。
- 本番ビルド、noindex解除、日英言語情報、sitemap、GA4受信の確認前に「実験開始済み」と記録しない。

### 共通の更新判断

- Search Console のクエリ、表示、クリック、流入ページを確認する
- 同じクエリに複数記事が出る場合は、順位だけでなく検索意図の一致を確認する
- 変動情報は定期更新し、技術解説は一次情報の変更時に見直す
- 短期の順位変動だけを理由に頻繁にタイトルを変えない
- 追加より、既存記事の正確性、重複解消、内部リンク改善が有効な場合はそちらを優先する
