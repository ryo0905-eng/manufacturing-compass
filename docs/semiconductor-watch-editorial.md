# 業界ウォッチ：テーマ探索と確認付き編集

更新日：2026-10-18。

## 現行UIと日次確認

watchの主役は主要12社の最大20期の年次カード。白地・最大1180px、1280px以上6列、1024〜1279px4列、768〜1023px3列、767px以下2列。最小180px高で内容に合わせて伸ばし、12px角丸、薄い罫線、10pxの間隔。企業名14pxは省略せず折返し、数値22〜24px、補足11px。既存ロゴはPC・スマホとも最大48×20pxの枠に表示し、取得失敗時は企業名を残す。強い装飾・初期アニメーションは使わない。

初期は売上高・10年・売上高順。売上高／営業利益率と5／10／20年を一括切替する。売上高は直近通期の円換算額を「約○兆円／○億円」で大きく表示し、期末年月と原通貨から算出した前年比を添える。グラフは円換算売上の棒、営業利益率は%の折れ線。共通縦軸は指標・期間ごとに全12社から求め、テーマ変更で動かさず、極端な値も切らない。売上高は0円始まり、上端・中間・0の3目盛りと兆円／億円の単位を表示する。利益率は最大3目盛りで0%を優先し、重なる端のラベルを省く。グラフ本体は48px高、横軸は実際の期末日。欠測を埋めず、期末年月・連結／部門範囲と「各社で決算期・対象範囲が異なる」を明示する。

円換算は`src/data/watch-exchange-rates.json`の同一基準日のレートを全社・全期間へ適用する。「同一為替で円換算した規模比較用の概算」、為替基準日、FRB H.10の出典を常設し、過去当時の円建て実績と区別する。原通貨実績は変更しない。初回は2026-10-09の原値（2026-10-13公表・2026-10-18確認）。ドル当たり円・ウォン・台湾ドルと、ユーロ当たりドルの方向を保持し、円へのクロスレートを導出する。閲覧時取得・日次自動更新は追加しない。更新手順は[決算運用](./earnings-ir-operations.md)を参照。

売上高カードだけを円換算売上高順／売上前年比順で切替。営業利益率は利益率順とし、売上高へ戻ると直前の売上高の並び順を復元する。丸め前の直近通期値を降順、算出不可は末尾、同値は元の企業順とする。最新四半期の値や期間全体の成長率で並べない。下段の最新四半期・ニュースの順序は変更しない。現在の並び順を一覧上へ明記する。

一覧ではホバー・左右キーで最寄りの期を選び、年月・円換算額・原通貨額・範囲（利益率では年月・率）と欠測理由をカード内の数値表示へ出す。Home／Endは最初／最後、Escape・フォーカス離脱で数値表示を閉じる。指標・期間変更時は選択をリセットする。グラフは独立したフォーカス可能な操作領域とし、企業名・主数値と末尾の「業績・出典を見る」の通常文書リンクから企業別`?years=…#annual-history`へ進む。

グラフのクリック・タップ、または各カードの「拡大」ボタンでネイティブdialogを開く。PCは最大960pxの中央表示、767px以下は全画面。5／10／20年と選択期を引き継ぎ、未選択時は直近期。拡大内の期間切替は設けず、URLは変更しない。売上高は青い棒・左軸（円換算）、営業利益率はオレンジの線・右軸（%）とし、両軸は企業・期間ごとの全有効値から独立に算出。「企業ごとの目盛り」、軸名・単位・凡例を常設し、棒と線の高さの一致は数値の一致や相関を意味しないと説明する。売上高は0始まり、利益率は赤字を含む全値と0%を表示し、欠測や比較不能な境界で線を切る。

拡大内はホバー・タップ・左右キー／Home／Endで期を選び、同一期の両指標、売上高の原通貨・前年比、範囲・会計基準・算出値・欠測理由を数値欄へ表示する。掲載期数・不足理由・数値確認日・為替基準日・FRB出典・期間付き企業別リンクも保持。オレンジの破線は利益率0%、縦の茶色の点線は比較の区切り。閉じるボタン・Escape・背景のクリックで閉じ、背景へのドラッグでは閉じない。表示中は背景スクロールを止め、終了時にスクロール制御と起点のフォーカスを復帰する。初期HTMLの数値表とリンクは維持し、追加取得・保存・日次タスク対象の拡張は行わない。

前年比は切出し前の原通貨実績から「（本期売上高÷前年売上高−1）×100」で算出する。最初の表示年も期間外の前年を参照し、前年欠測・前年売上ゼロ以下・比較不能な期間／基準／範囲／通貨／単位変更では算出しない。金額自体は取得済みなら境界でも表示し、境界線と注記を付ける。直近期の欠測を過去値で代用せず、利益率の線も欠測・境界を接続しない。Samsung DS部門・KLA営業利益の算出値を維持。初期HTMLの数値表には原通貨売上・円換算額・前年期末日／前年売上・前年比・算出不可理由・各期の範囲を保持し、利益率では営業利益と式も残す。

`#theme=…&company=…&metric=…&years=…&sort=growth`で状態と戻る／進むを復元。指標IDはrevenue（売上高）／operating_margin。旧operating_income・不正値は売上高へ戻す。sort=growthだけを保存し、無指定・不正値は売上高順。利益率表示中も売上高側のsortを保持する。期間は5／10／20、不正値は10。テーマ・指標変更で期間を保持し、企業は明示した有効IDだけ強調する。旧ニュースアンカー・展開・計測を維持する。

大きな要点パネルと横長の前年比棒グラフは使わない。最新四半期の金額・前年比・期間・範囲・要点・出典・確認状態・次回決算は「最新四半期の決算一覧」のdetailsへ保持。テーマに連動する30日ニュースは初期5件と残りのdetails、14日間の予定・過去掲載・背景・公式リンクは下段で展開する。ニュースは元資料の公表日で判定し、同じ決算原資料は重複させない。

earningsは12社の売上・営業利益・前年比・数値範囲・要点・次回予定を先に表示する。企業の最新発表確認・予定・候補判断はwatch-calendar.jsonで共有。候補収集と原資料確認、数値確認と内容変更を分け、取得失敗時は前回正常データを保持する。取得で記事の公表日を変えない。

記事の背景・企業・用語は従来のwatch-editorial.jsonを使用する。highlightsは旧構成との互換用に保持し、現行の冒頭選定には使わない。日次処理の範囲・固定許可ファイル・登録本文・未稼働状態は [watch-daily-operations.md](./watch-daily-operations.md) に従う。既存のAI公開ゲートは無効のまま。

## 最大20期の企業分析（2026-10-18）

watchは12社の通期カードと対応数値表、企業別`?years=…#annual-history`への入口を持つ。企業別・比較とも5／10／20年、既定10年。各社の最新公表済み通期を終点として日付で絞り、欠測を古い期で穴埋めしない。20期未満は実際の掲載期数と不足理由を表示する。企業別は売上高と営業利益を同じ原通貨・同じ軸の棒グラフ、利益率を別の線グラフにし、期末日の目盛りを間引く。数値表と出典は初期HTMLに常設し、期間・範囲・基準・確認日・数値ごとの根拠を表示する。

「長期推移を読む」は最大3件。対象期、会社の説明／編集上の解釈、出典URLと該当箇所、確認日を表示する。直近四半期の補足は通期注記と区別する。AI・HBM・データセンターだけでなく、市況・買収・再編も読む。全社増収をAI需要の寄与額とは扱わない。

比較は「年次推移」を初期表示に「最新四半期」を切替。装置・メモリ関連で2〜3社を選び、比較実行後に図と表を更新する。利益率が初期指標で、売上高指数へ切替可能。実際の期末日を横軸にし、指数は選択期間内で直近期につながる比較可能区間の最古期を100とする。起点の日付・掲載期数・対応表で対象期間を示す。基準値が欠測・ゼロ以下なら算出しない。金額の為替換算はしない。欠測・会計基準・範囲・通貨変更・比較不能な境界を接続しない。

企業別・比較は同名クエリ`years`で期間を引き継ぐ。`group/company`は既知企業・同一群で照合し、不正指定は群の初期2社へ戻す。期間指定付き企業別・条件付き比較URLはnoindex/follow、canonicalは基底URL。戻る／進むで期間を復元し、初期表示・履歴復元・同じ期間の再押下ではイベントを送らない。watchは`cards-v2`、年次操作は`annual-v2`。属性は[計測仕様](./conversion-architecture.md)を参照。

2026-10-18の旧カード（4／3／2列・高さ220px）は実Chromeで1280・1024・768・390・320pxの表示と操作を確認済み。今回の6列・円換算棒グラフ・ロゴ・数値操作・並べ替えへの変更はブラウザ操作を対象に含めず、実画面は未確認。詳細な実行結果と未完了のテストはTASKSへ記録。本番反映・GA4受信は未確認。収集・訂正は[決算運用](./earnings-ir-operations.md)、12社の範囲・不足理由・境界は[収集記録](./earnings-long-history-audit.md)を参照する。

## 画面とデータの境界

- `/semiconductor-watch`：状況と今回の要点 → 5テーマ → 注目1件＋補助最大2件 → テーマ別一覧 → 掲載・確認ログ → 公式リンクと更新方針。
- ニュース5件、決算9社、工場5案件を初期表示。全体では主テーマ1つ、テーマ選択時は明示された副テーマも使用。テーマはAI・メモリ／製造装置・材料／設計・受託製造／先端実装・後工程／工場・設備投資。「決算」は種別であってテーマではない。
- 注目は編集指定。人気、順位、重要度スコア、架空の件数を使わない。記事不足なら指定できる実数だけ表示。
- `/semiconductor-watch/[slug]`：要約と日付 → 事実 → 背景・編集上の見方 → 数値・状態・一般工程図 → 未確認点 → 用語 → 目的別リンク最大3件 → 正式資料・短い根拠抜粋・改訂履歴。独立URL、canonical、NewsArticle、sitemapを維持。
- PCは注目の大小と本文／補足の2列、760px以下は1列。本文16px、テーマボタン44px以上。画像・新ライブラリなし。数値・期間・事業範囲を図自体に表示し、一般工程図は取引関係を示さないと明示。
- `chip-pulse-media.json` は事実の正本。`earnings-snapshot.json` と `factory-projects.ts` の数値を複製せず、`src/lib/watch.ts` で同じデータから表示用項目を組み立てる。
- `watch-editorial.json` は注目ID、記事版、背景、確認日、出典、企業ID、テーマ、用語、探索先だけを管理。記事版・出典URLの不一致や `sourceCheck:changed` があると、その背景・関連先を出さず再確認中と表示する。出典変更の記事は注目から外す。
- 企業IDは企業DB、地図の企業選択は描画対象に存在するIDのみ。ASEは補助企業として地図へ、Broadcomはファブレスのセグメントへ案内する。工場カードは既存の案件解説へ進む。
- 記事の公表日、サイト掲載日、記事改訂日、背景確認日、収集確認日を区別。「日次集計対象の発表数」は掲載作業の件数ではない。0件、部分取得失敗、編集停止は別表示。編集7日／収集2日超を注意表示し、ページを1時間ごとに再生成する。
- フィルターは `#theme=…`、従来の `#signal-{id}` も残す。ブラウザの戻る操作でテーマを復元。初期HTMLには全項目があるのでJavaScriptなしでも詳細・原文を読める。

## 週2〜3回の編集手順

日次の候補収集と確認付きの記事公開は別工程。週2〜3回は編集の目安であり、自動実行の予約や掲載数の約束ではない。AIポリシーの `approved:false` は維持する。

1. `npm run chip-pulse:update` で候補を収集。`.private/chip-pulse-candidates/current.json` と最終試行を確認する。失敗時は成功と記録しない。
2. SEC14社の直近30日と、日本の手動調査対象を確認。既存ニュース・決算と同じ発表は新規ニュースに数えず、既存詳細へ関連づける。
3. 公式原文を開き、主張、金額・単位、期間、時制、計画／実績、企業・工程の分類を照合する。本文全文は公開しない。原文抜粋は必要な短い範囲に限る。公開禁止辞書と個人・機密情報も確認する。
4. 私有候補JSONを作る。記事配列 `articles`、照合に使った文書／抜粋の `documents:[{url,text}]` を含める。各記事は現在の `NewsArticle` 項目に加え `review:{facts:true,numbers:true,redaction:true}` を持つ。新規は `version:1`、改訂は前回＋1。これは編集者／エージェントが実際に完了した確認を記録する値で、内容の正しさを自動で保証するフラグではない。
5. `npm run chip-pulse:editor -- --candidate .private/chip-pulse-editor/YYYY-MM-DD.json`。ID、HTTPS出典、カレンダー日、日時精度・順序、分類、図の形式、根拠抜粋の一致、版、記事間参照、重複URLを検証する。検証失敗時は公開JSONを書かない。成功時は前回版を `.private/chip-pulse-editor-archive` へ保存し、原子的に置換する。掲載日時と改訂履歴はコマンドが生成する。
6. `watch-editorial.json` に企業ID・主／副テーマ・背景・用語・関連先を登録。`version` と `sourceUrls` を記事に一致させ、実際の `checkedAt` を記録する。`highlights` は `article:{id}` / `earnings:{id}` / `factory:{id}` の最大3件。数値や工場実績はここに複製しない。
7. 原文を既存 `fetchDocument` と同じ方法で取得した全文ハッシュを運用台帳へ保存し、以後の差分検知の基準にする。独自の短い抜粋のハッシュで代用しない。初回3件は原文取得・抜粋一致を確認して保存済み。日次処理は確認付き記事の本文を上書きせず、出典変更だけをフラグで通知する。30日候補窓の外の記事は日次の変更検知対象外なので、再度注目に選ぶ時に原文を再確認する。
8. `npm run chip-pulse:editor -- --check` と `npm run chip-pulse:test` で記事・参照整合を確認。必要な型チェックはリポジトリの回数制限内で行う。差分・公開禁止情報を確認し、公開設定を整える。commit・push・本番反映は別の操作。
9. 編集記録へ、候補ID、採用／既存へ接続／見送り、理由、確認日時を残す。候補確認・原文確認・編集・掲載それぞれの開始終了を実測する。資料不足なら本数合わせをしない。

旧 `chip-pulse:publish` は旧メタデータ形式向け。確認付き記事の登録には使わない。初回候補は `.private/chip-pulse-editor/2026-10-04.json` に保存したが、公開運用例に原文全文や環境変数をコピーしない。
