# トップの横断検索と目的別ナビゲーション

最終更新日: 2026-10-25

## 目的と範囲

既存の公開情報を、名前や用語から探す入口と、目的からたどる入口を揃える。日本語トップと共通ヘッダーを対象とし、[Semirai](https://semirai.com/)の横断検索・目的別導線を参考にした（参照日: 2026-10-25）。

トップは紹介文・画像、検索、4つの目的別入口、ランキングの順。技術は工程の記事シリーズ→工程の体験→実務ツール、企業・業界はランキング→業界地図→企業比較、工場・拠点は国内拠点マップ→新設・増設一覧、仕事・キャリアは職種マップ→Career Compass→転職の軸ノートへ案内する。入口はPC2列、720px以下1列。ランキング以降は既存の情報を使う。

## 共通メニュー

`src/data/site-navigation.ts`をリンク・グループ・トップの道順の正本とする。`header.ts`は既存のリンク監査向けに同じ定義を平坦化する。

4グループは技術、企業・業界、工場・拠点、仕事・キャリア。企業・業界には業界ウォッチと企業・装置・材料記事、仕事・キャリアには相談準備と実体験記事も含める。検索・記事一覧は独立リンク、Career Compassは既存の独立CTAを1つだけ表示する。

- 1160px以上はボタンで1グループだけ開くドロップダウン。未満は開閉メニュー内でグループごとのリンクをまとめて表示する。CSSとJavaScriptの境界を揃える。
- Escape、外側クリック、フォーカス離脱、リンク選択、パス・hashの変更、画面幅の切り替えで閉じる。Escapeは開いていたグループのボタン、スマホではメニューボタンへフォーカスを戻す。
- 現在地はアンカーなしの最長一致リンクに示す。`/segments/*`は業界地図の配下として扱い、アンカー付きの案内をページ全体の現在地と誤認させない。
- 「検索」は`/#home-search`へ移動する。トップ到着時、hash変更時、トップでの再選択時に検索入力へフォーカスし、追従ヘッダー分の余白を確保する。

## 検索のデータと操作

`site-search-index.ts`がサーバー側で検索メタデータを生成し、`SiteSearch`へ渡す。`SiteSearchEntry`は固定ID、種別、タイトル、説明、リンク先、検索用語だけを持つ。記事本文、取材記録、出典台帳などをクライアントへ渡さない。

- 公開済み記事、業界地図の掲載企業、公開中の`learningTools`、共通ナビの案内ページが対象。公開条件付きツールは既存カタログの公開判定を使う。
- 企業は`isCompanyIndexable`を満たせば個別詳細へ、その他は`/industry-map#company=固定ID`の概要へ案内する。サイト全体の企業公開設定を検索用に変更しない。
- 記事・ツールと案内ページでURLが重なる場合は記事・ツールを優先し、案内名を検索用語として合流する。
- 全半角・英字大小・連続空白を正規化し、空白区切りの全語が含まれるものを表示する。タイトル完全一致、別名完全一致、タイトル内一致、検索用語内一致、説明文を含む一致の順。同順位は元の順とする。
- 入力に合わせて検索するが、日本語変換中は直前の結果を保持し、変換確定時に更新する。検索例はCpk、エッチング、東京エレクトロン、職種。
- すべて／記事／企業／ツール／案内ページで絞り込み、初期12件・追加12件。語や種別の変更で12件へ戻す。追加表示時は最初の追加結果へフォーカスする。
- 未入力時は検索例、0件時は短い語での再検索と既存の3一覧を案内する。JavaScript無効時も目的別リンクから移動できる。
- 検索語をURL、ブラウザ保存領域、計測へ書き込まない。検索API・検索専用URLは追加せず、canonical・構造化データ・sitemapは既存ページを使う。

## 計測と公開後の観察

| イベント | タイミング | 属性 |
| --- | --- | --- |
| site_search_start | 変換確定済みの空白以外の入力・例の選択による初回検索。マウント中1回 | result_kind、result_count |
| site_search_filter | 検索結果の種類を変更したとき | result_kind、result_count |
| site_search_result_click | 検索結果を選択したとき | result_id、result_kind |

検索イベントに入れるのは固定ID・種別・件数のみ。結果クリックは専用イベント1つとし、記事・トップ・Career Compassのイベントを重ねない。通常のトップ道順は既存`home_link_click`のsection_id=heroと固定destination_id、Career Compassだけは既存の専用CTAイベントを使う。ヘッダーは既存`header_nav_click`とdesktop/mobile_menuを使う。独立Career Compass CTAの既存イベントも維持する。

本番反映日から28日間、検索開始→結果クリック、種類別の結果クリック、メニューから各ページへの遷移を観察する。イベント件数をそのまま人数の転換率にしない。GA4の受信確認と本番反映日を記録してから期間を数える。
