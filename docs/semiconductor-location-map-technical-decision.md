# 日本の半導体企業・拠点マップ 技術選定

最終更新日: 2026-09-04

## 状態

公開MVPへ進む場合の暫定採用案です。実装、依存パッケージの追加、地図タイルへの接続はまだ行っていません。

人による代表10拠点の座標レビュー後に最終確定します。レビューで住所検索結果の修正率が高い場合は、座標作成方法を再検討します。

## 結論

| レイヤー | MVPの採用案 | 役割 |
| --- | --- | --- |
| 地図表示 | Leaflet 1.9系 | 50〜70拠点のピン、選択、移動、ズームだけを担う |
| 背景地図 | 国土地理院「淡色地図」のXYZタイル | 日本国内の拠点を読みやすく表示する |
| 拠点データ | `src/data` のローカル静的データ | 初期HTMLの一覧と地図で同じ確定データを使う |
| 座標作成 | ABR Geocoderを編集時に自前実行 | 企業公式住所を正規化し、暫定座標を作る |
| 座標確定 | 公式地図または施設情報との照合＋人による確認 | 別施設や市区町村代表点を公開しない |
| 求人状態 | 拠点とは別の期限付き静的データ | 地図の存在情報と募集中表示を混同しない |

実行時の住所検索API、Google Maps API、Mapbox API、データベースはMVPに導入しません。

## この構成を選ぶ理由

### Leaflet

- MVPは50〜70拠点で、3D表示や大規模なベクトルタイル描画を必要としない
- ピン、ポップアップ、GeoJSON、タッチ操作、XYZタイルを標準機能で扱える
- Leaflet 1.9系は安定版として運用実績があり、2.0系アルファ版は採用しない
- 地図だけを小さなClient Componentに閉じ込め、一覧、説明、内部リンクはServer Componentで出力できる
- 背景地図の提供者を差し替えられるため、地図ライブラリと地図データを分離できる

Leafletは地図画像を提供しません。ライブラリ自体のライセンスだけでなく、背景タイル側の利用条件を別に守ります。

### 地理院の淡色地図

- 日本国内の都道府県、市区町村、道路との位置関係を確認しやすい
- 派手な色が少なく、企業カテゴリ別のピンや選択状態を重ねやすい
- 地理院タイル一覧では、ウェブサイトやアプリケーションがタイルをリアルタイムに読み込む利用は、出典明示により申請不要と案内されている
- APIキーや従量課金をMVPへ追加せずに検証できる

地図内に「地理院タイル」への可視の出典リンクを常時表示します。タイルURLは一か所の設定へまとめ、利用条件や提供状況が変わった場合に差し替えられるようにします。

### 編集時だけABR Geocoderを使う

- 企業住所は運営側が追加・更新するため、ユーザー入力を実行時に検索する必要がない
- ABR Geocoderはデジタル庁が公開するMITライセンスのソフトウェアで、自前実行手順が公開されている
- 公開候補がある都道府県だけを編集環境へ取り込み、全国データを常時運用しない
- 座標生成を編集工程に限定すれば、公開アプリにジオコーダ、APIキー、住所ログ、外部API障害を持ち込まずに済む
- 住所検索結果をそのまま公開せず、精度区分と目視レビューを必須にできる

ABRのデータには公共データ利用規約が適用され、出典表示と、加工した場合の明示が必要です。初期は住居表示までの `rsdtdsp` を使い、追加の利用条件がある地番関連データは必要な拠点だけ個別確認します。

## 確定した利用方法と出典表記

### 地理院タイル

背景地図は淡色地図をブラウザからリアルタイムに読み込み、地図内の見える位置へ次のリンクを常時表示します。

```text
地理院タイル
```

リンク先は `https://maps.gsi.go.jp/development/ichiran.html` とします。画像のダウンロード、再配布、別タイルの混在をMVPへ含めません。

### ABR Geocoder

初回の住所検索は、対象都道府県と `rsdtdsp` カテゴリを使います。`rsdtdsp` は都道府県、市区町村、町字、住居表示を対象とし、地番データを含みません。

公開ページの情報源欄に、ABR由来の座標が一件でもある場合は次の表記を置きます。

```text
位置情報の一部は「アドレス・ベース・レジストリ」（デジタル庁）をもとにManufacturing Compassが加工して作成
```

「アドレス・ベース・レジストリ」から `https://www.digital.go.jp/policies/base_registry_address` へリンクし、利用規約URLと確認日を座標ソースデータにも保持します。

工業団地など、住居表示では十分な位置を得られない場合だけ `parcel` を候補にします。地番マスターと地番マスター位置参照には追加規約が適用されるため、使用前に対象データ、出典、利用規約を個別確認します。確認できるまでは `parcel` の結果を `照合専用` とし、本番データへ移しません。

### パイロットで使った第三者地図

- Q地図APIの出力は精度比較だけに使用し、本番の座標ソースにしない
- OpenStreetMapの施設座標は目視照合だけに使用し、本番の座標ソースにしない
- Google Mapsへの企業公式リンクは所在地確認の補助に使用し、URL内座標を抽出して本番データへ保存しない

これらを本番利用する必要が生じた場合は、提供者ごとの保存、再表示、帰属表示、派生データの条件を改めて確認します。

## データ作成フロー

```text
企業公式ページで正式住所を確認
  → ABR Geocoderを編集環境で実行
  → 一致レベルと暫定座標を保存
  → 企業公式の地図・拠点情報と照合
  → 人が背景地図上で位置を確認
  → human-reviewed の座標だけ公開データへ移す
```

公開後のページ表示時に住所から座標を生成しません。公開データには緯度経度だけでなく、次を追跡できる情報を持たせます。

- 座標の取得方法
- 施設、地番、住居表示、町字などの精度
- 座標ソースID
- ソースの提供者と利用条件URL
- 必要な出典表記
- 自動確認または人による確認の状態
- 最終確認日

## SEOとコンポーネント境界

地図が読み込めない状態でも、ページの中心価値を失わない構成にします。

```text
Server Component
  ページ見出し、説明、件数、拠点一覧、企業リンク、構造化データ

Client Component
  Leaflet地図、ピン選択、一覧との同期、地図表示切り替え
```

検索条件はServer Componentが受け取れる有限のURLパラメータへ正規化します。自由な組み合わせをindexさせず、全国ページと公開基準を満たす都道府県ページだけを検索入口にします。

## MVPでは採用しない案

### MapLibre GL JS

ベクトル地図、細かなスタイル変更、大量データには有力です。ただし現時点の50〜70拠点には過剰で、WebGLとworkerの組み込み確認が追加で必要になります。500拠点規模、行政区域の塗り分け、ベクトルタイルが必要になった時点で再評価します。

### Google Maps / Mapbox

住所検索、経路、周辺施設などが必要になれば再検討します。MVPではAPIキー、課金管理、保存・表示条件を追加するほどの機能を使わないため採用しません。

### OpenStreetMap標準タイルの直接利用

OSMデータは利用できますが、`tile.openstreetmap.org` は寄付で運営されるベストエフォートのサービスで、利用ポリシー上、可視の帰属表示、キャッシュ、Refererなどの条件があります。公開サービスの既定タイルにはせず、OSM由来の施設座標を採用する場合だけODbLと出典条件を個別に管理します。
