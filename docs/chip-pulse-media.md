## 30日供給調査

実データは `docs/data/chip-pulse-supply-audit.json`。`report.days` はJSTの日別の候補数・ID重複整理後・本文取得・掲載可確認済み・分野別件数。`weeks` は調査末日から7日ずつの非重複4区間。未評価記事を「掲載不可」と断定するものではなく、`publishable` は確認できた下限値。

2026-08-29〜09-27の調査：取得14/14社成功、候補8件、本文取得7件、掲載可確認済み2件。平日の確認済み中央値0件。最多でも候補8件しかなく、週10件／平日中央値2件／週4分野の目標を達成できない。米国開示、設計・製造に偏り、装置・材料・メモリの鮮度が不足する。

SEC APIには提出日に加え受理日時がある。受理日時を**SEC上での公表日時**として表示し、元の企業発表日時と同一だとは扱わない。日付しかない場合は時刻を補わず、06:00境界の当日版には入れず一覧に残す。企業の一般的な事業から記事分野を推測しない。

## 更新・データの境界

- `chip-pulse-media.json`：公開記事、公式リンク、現在版、取得状態。`operations.json`：処理済みID／ハッシュ、予算、過去版のID一覧。Gitで実行間保持する。記事改訂の旧見出し・要約・版番号も保持する。
- 朝刊は前日06:00以上〜当日06:00未満（JST）。06:17取得、07:00頃反映を目安とし完了時刻は保証しない。06:00前の手動実行は前の版を使う。
- 元の公表日時、初回掲載、記事更新、取得確認は別項目。取得確認だけでは内容更新日時を進めない。全失敗時は版・内容・内容日時を維持し、失敗状態だけ更新する。
- 元URL正規化、出典ID、`chip-pulse-source-aliases.json` の明示対応で統合。見出し類似度だけで記事を削除しない。別の提出は別項目。続報の `relatedIds` は確認した関係だけを編集登録する。
- 本文ハッシュが同じ生成失敗記事は自動再課金しない。手動確認済み記事の原文変更は要約を上書きせず再確認表示へ戻す。検証に通った自動記事の改訂は旧版を残す。
- エラー時はその取得先の前回リンク・記事・正常確認時刻を保持。処理終了コード1でもActionsの後段で成功分と失敗状態を保存する。SEC連絡先自体が未設定の場合は前回ファイルを維持して設定エラーにする。
- 本文断片しか処理しない場合は範囲限定の要約とする。全文を読んだような主張や自動の独自考察は追加しない。

## AIの境界と予算

候補は既存AI SDK＋Vercel AI Gateway。ツール権限は与えない。外部文書をJSON内の信頼できないデータとして渡す。1記事は最大2呼び出し（生成・別呼び出しで意味照合）、SDK再試行0回、各入力24,000 UTF-8 bytes以内、出力2,048 tokens、タイムアウト25秒。本文・画像・閲覧者データをページ閲覧時に送信しない。

公開ゲートは列挙値・型・完全一致の原文抜粋・数値・会社名、続いて全主張の数値/単位/日付/時制/計画と実績/分類の意味照合。AI照合は事実保証ではない。記事では「AIによる事実要約」と区別する。背景は出典付き既存解説へのリンク、推測の影響は自動生成しない。

2026-09-27に[Google公式料金](https://ai.google.dev/gemini-api/docs/pricing)と[Vercel公式モデル一覧](https://ai-gateway.vercel.sh/v1/models)を確認：Flash-Lite $0.10/$0.40、Flash $0.30/$2.50（100万入力/出力トークン、標準）。[Gateway料金](https://vercel.com/docs/ai-gateway/pricing)も参照。比較結果は `docs/data/chip-pulse-model-eval.json`。2資料という小標本で、いずれもゲートを通過せずモデルは暫定候補にとどまる。

- 月1,000円を呼び出し**前**に上限判定。Flash-Liteは最大入力・出力を見込み、1ドル275円までの余裕込みで1呼び出し1円、1記事2円を予約。10件×31日で620円の予約上限（比較試験別）。失敗や未使用分を払い戻さない保守的な台帳。
- 今回の比較試験は20円を予約。これは実請求額ではない。4つの編集試行を当日上限に算入。
- 承認ポリシー＋直近31日以内の確認済み為替＋環境変数の有効化が必要。価格一覧の欠損・値上げ・為替条件失効では呼び出さない。
- Actionsでは予約台帳を**先にcommit/push**できた時だけ課金処理へ進む。実行ID＋再実行番号で一意化。クラッシュ・後段push失敗でも上限予約は消えない。並列実行を禁止する。
- キーなし／精度承認なし／上限到達時は公式リンクの更新だけ継続。架空ニュースへフォールバックしない。ほかの機能で同じキーを使う費用はこの台帳の対象外。

## UI・SEO・画像

背景 #101316、記事面 #181e23、本文 #f2f4f5、アクセント #77dfec。最大1120px、本文720px、スマホ1列。本文16px、見出し20〜24px。分野選択は一覧だけに作用し、当日版は全体固定。KPI・テーマ件数グラフ・株価ヒートマップをトップから除き、業界地図・基準日のあるランキングへ接続する。

記事は既存IDをslugとし、`#signal-{id}` も維持。未再確認の旧記事は掲載を移さないため、その旧IDの根拠表示は復元しない。要約のない公式項目は外部リンクだけ。記事のcanonical、パンくず構造化データ、NewsArticle、sitemapを追加。記事公表日時はこのサイトでの初回掲載、元資料の公表日時を本文で別表示する。

工程ビジュアルは自前SVG。画像の自動取得・外部ホットリンク・企業ロゴ転用はしない。公式画像追加時は利用条件を確認し、`public/images/chip-pulse/` のローカル画像とalt・credit・HTTPS creditUrlを登録。空欄、外部画像、パストラバーサルを拒否。読み込み失敗で同じ16:9の工程図へ戻す。

## 操作と残る設定

```bash
npm run chip-pulse:audit   # 原文・メタデータの供給調査。AI呼び出しなし
npm run chip-pulse:refresh # ポリシー無効なら公式リンクだけ更新
npm run chip-pulse:test
```

既存の `CHIP_PULSE_SEC_USER_AGENT` Secretは継続。将来の自動要約には `AI_GATEWAY_API_KEY` Secret、Repository Variable `CHIP_PULSE_AI_ENABLED=true`、精度ゲート改善後のポリシー承認・為替確認が必要。Secretだけで有効化されない。モデル比較を課金再試行する際は、新しい評価設計と予算予約を行い、既存の試験ID・台帳を消さない。

デフォルトブランチへ反映後、Actions手動実行→bot更新→Vercelの成功→翌朝の定期実行を確認。その後7日間、候補・本文・掲載・分野・エラー・予約費用を記録する。既存計測で `chip_pulse_article_view`、`chip_pulse_read`（article/source/background）、`chip_pulse_filter_change` を分け、記事量と読まれる価値を別に評価する。本番のイベント受信は未確認。
