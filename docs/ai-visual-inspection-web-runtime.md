# AI外観検査：端末内推論基盤の実装記録

更新日: 2026-09-22

## 現状

Worker・ONNX Runtime Web WASMの実装と静的アセットの準備まで完了。**WASMの数値照合は未通過**。オフライン最終評価の合格とは分けて扱い、比較UI・公開導線の実装へはまだ進めていない。

固定したシード17の4モデルをそのまま採用し、学習・しきい値・最終評価群は変更していない。エクスポート前に最終評価ロックの全ハッシュを照合した。

## 実装

- `src/lib/ai-visual-inspection/protocol.ts`: ラベル・真値を含めない要求、完了または失敗の応答。
- `runtime.ts`: モデルの遅延取得とSHA-256確認、WASM単一スレッド、実画素の明るさ変換、1セッション・最大24枚のスコアキャッシュ。画素のハッシュで照合するため、同じ画像番号でも画素が変われば再推論する。しきい値だけなら再集計。
- `inference.worker.ts`: 推論は直列実行。新しい要求を優先し、画像間で中断を確認する。全件完了時のみ結果を返す。
- `client.ts`: 古い応答を無視。新しい操作・破棄時は待機を解除。起動失敗・実行失敗・60秒タイムアウトではPromiseを失敗させる。UIは処理中・失敗時にAI集計を未評価へ戻す必要がある。
- `public/ai-visual-inspection/v2/`: 固定モデル、同一版のJS/WASM、MITライセンス・第三者通知・教材の利用条件。外部CDN/APIは使わない。現在は操作画面から未接続。
- `export_web.py`: ロック確認後に4モデルを出力。開発用先頭24枚×4モデル×3倍率のPython参照を非公開キャッシュへ生成。最終群を新たな調整には使わない。
- `sync_web.cjs`: TypeScriptから静的WorkerのES modulesを生成し、固定版ランタイムをコピー。`assets.json` にサイズ・gzip試算・ハッシュを記録する。ソース変更時は再実行し、生成済みJSを直接編集しない。

ONNX Runtime Webは1.22.0に固定。`numThreads=1`、`proxy=false`、同じ版のWASMを同一サイトから取得する。設定根拠は[公式環境設定](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)。ライブラリ更新時はモデルとの数値一致と配信物を再検証する。

## 検証結果

| 検証 | 結果 |
|---|---|
| 固定モデル・データ・処理のロック照合、参照生成 | 通過 |
| 既存の画素・連結成分・集計テスト | 通過 |
| Clientの古い応答、操作切替、失敗、再試行、破棄 | 通過（Worker代替実装） |
| Runtimeのキャッシュ、明るさ変更、モデル切替、無効出力拒否、Tensor解放 | 通過（推論代替実装） |
| 型チェック | `npm run typecheck` 1回、通過。Node 22使用 |
| 実WASMとPython参照の一致 | **失敗・未完了**。Node 22から実WASMを実行し、基準モデル・倍率0.7の条件で `inspectScores` が「AIの出力が不正です。」を返した |
| ブラウザ・スマホ・Next.jsとの接続 | 未実施 |

WASMの失敗は、スコアに非有限値または0〜1の範囲外値があったことを示す。初回テストでは値の詳細を保存していないため、原因を特定していない。微小な浮動小数点誤差とはまだ断定できない。失敗した検証は別設定で再実行せず終了した。次回の調査用にモデル・倍率・画像番号・画素番号・値・最小最大値の記録をテストへ追加したが、その追加後のWASM再実行は未実施。

スコアを無条件に丸めたり、異常を良品判定に変えたりする修正はしていない。オフライン精度の基準も変更していない。

## 容量と残るゲート

1モデル477,448 bytes。推論用JS・WASM・manifest・モデル1個のgzip合計試算は **3,332,134 bytes（約3.33 MB）**。ローカルでgzip level 9を適用した値であり、HTTP実転送量ではない。将来のUIバンドルは含まない。`assets.json` にファイル別の値を記録する。

ブラウザ初回取得、読み込み失敗、連続操作の実Worker挙動、ウォーム推論、24枚一括評価、スマホの実端末性能は未測定。NodeでのWASM実行をブラウザの測定と呼ばない。UIがないため公開プライバシーページ・サイト導線は変更していない。ブラウザ確認はリポジトリの実行方針に従い、UI実装後の依頼時に行う。

次の作業はWASM異常値の特定。微小な範囲逸脱だった場合も許容幅・処理方法を明示し、全4モデル×3倍率のスコア誤差1e-4以内・検出領域完全一致を再確認する。非有限値や大きな逸脱なら、出力の補正で隠さず演算・ランタイムを調査する。通過後にブラウザ接続と比較UIへ進む。
