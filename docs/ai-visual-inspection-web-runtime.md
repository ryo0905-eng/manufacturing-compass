# AI外観検査：端末内推論基盤の実装記録

更新日: 2026-09-22

## 現状

Worker・ONNX Runtime Web WASMの実装と静的アセットの準備まで完了。**Node上の実WASMで数値照合が通過**。オフライン最終評価・ブラウザ実行の確認とは分けて扱う。[比較UI](./ai-visual-inspection-ui.md)は実装済み。トップ・ツール一覧・GRRの試用版導線は追加済み。検索公開は保留。

固定したシード17の4モデルをそのまま採用し、学習・しきい値・最終評価群は変更していない。エクスポート前に最終評価ロックの全ハッシュを照合した。

## 実装

- `src/lib/ai-visual-inspection/protocol.ts`: ラベル・真値を含めない要求、完了または失敗の応答。
- `runtime.ts`: モデルの遅延取得とSHA-256確認、WASM単一スレッド、実画素の明るさ変換、1セッション・最大24枚のスコアキャッシュ。画素のハッシュで照合するため、同じ画像番号でも画素が変われば再推論する。しきい値だけなら再集計。
- `inference.worker.ts`: 推論は直列実行。新しい要求を優先し、画像間で中断を確認する。全件完了時のみ結果を返す。
- `client.ts`: 古い応答を無視。新しい操作・破棄時は待機を解除。起動失敗・実行失敗・60秒タイムアウトではPromiseを失敗させる。UIは処理中・失敗時にAI集計を未評価へ戻す必要がある。
- `public/ai-visual-inspection/v2/`: 固定モデル、同一版のJS/WASM、MITライセンス・第三者通知・教材の利用条件。外部CDN/APIは使わない。操作画面の開始ボタンから遅延接続。実ブラウザの接続・基本推論は確認したが、全項目通過ではない。[ブラウザ記録](./ai-visual-inspection-browser-validation.md)を参照。
- `export_web.py`: ロック確認後に4モデルを出力。開発用先頭24枚×4モデル×3倍率のPython参照を非公開キャッシュへ生成。最終群を新たな調整には使わない。
- `sync_web.cjs`: TypeScriptから静的WorkerのES modulesを生成し、固定版ランタイムをコピー。`assets.json` にサイズ・gzip試算・ハッシュを記録する。ソース変更時は再実行し、生成済みJSを直接編集しない。

ONNX Runtime Webは1.22.0に固定。`numThreads=1`、`proxy=false`、同じ版のWASMを同一サイトから取得する。設定根拠は[公式環境設定](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)。ライブラリ更新時はモデルとの数値一致と配信物を再検証する。

### 初回失敗と修正後の確認

初回の照合では、厳密な0〜1検査により失敗し、そのターンでは再実行しなかった。ユーザーの継続指示後、後処理前の出力を全12条件で調査した。全条件に微小な負値があり、最小値は `-1.1920928955078125e-7`、最大値は1。NaN・Infinityは0個。同じ負値はPythonのONNX参照にもあった。したがって「負値はすべて異常」とするWeb側の入力検査が、端点付近の数値誤差を拒否していた。

モデル出力の取り込み境界だけに `normalizeModelScores` を追加した。許容幅はfloat32の1付近のepsilonである `2^-23`（約0.000000119）。有限値かつ `[-2^-23, 1+2^-23]` 内の場合のみ0〜1へ補正し、それ以外は従来どおり未評価にする。`inspectScores` 自体の厳密な範囲検査は維持した。モデル・学習・しきい値・面積・合格条件を変更していない。

修正後の実WASM照合は1回で全12条件通過。補正後のスコアから作ったAI領域は、既存Python参照の領域と全件一致した。しきい値0.1〜0.9の各画素の判定も補正前後で変わらない。しきい値0は補正後の値を基準にすべての画素を選ぶため、補正前の負値との判定不変は主張しない（固定評価は0.5）。端点・許容幅超過・非有限値・入力非変更を単体テストし、実Runtimeがキャッシュ保存前に補正することも確認した。

調査値と修正後の照合値、モデル・参照・実装ハッシュは [数値記録](./ai-visual-inspection-wasm-validation.json) に保存。最終評価ロックの全ファイルが変更されていないことも照合した。調査と今回の照合は開発用先頭24枚を使用し、最終評価群の再推論は行っていない。

## 容量と残るゲート

1モデル477,448 bytes。推論用JS・WASM・manifest・モデル1個のgzip合計試算は **3,332,361 bytes（約3.33 MB）**。ローカルでgzip level 9を適用した値であり、HTTP実転送量ではない。将来のUIバンドルは含まない。`assets.json` にファイル別の値を記録する。

ブラウザ初回取得、読み込み失敗、連続操作の実Worker挙動、ウォーム推論、24枚一括評価、スマホの実端末性能は未測定。NodeでのWASM実行をブラウザの測定と呼ばない。UI追加時にプライバシーページを更新した。その後、ユーザー指示でトップ・一覧・GRRへの試用版導線を追加した。ブラウザ確認はリポジトリの実行方針に従い、UI実装後の依頼時に行う。

次は依頼時の実ブラウザ確認へ進む。今回の約1.66〜1.78秒／24枚はNode上で参照ファイル読み込み・画素比較・ルール計算を含むテスト全体の時間であり、推論速度やスマホ目標の達成根拠には使わない。
