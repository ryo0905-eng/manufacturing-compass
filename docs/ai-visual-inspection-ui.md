# AI外観検査：比較UIの実装記録

更新日: 2026-09-22

## 状態

`/tools/ai-visual-inspection` に5段階の試用画面を実装。Server Componentの概要・メタデータと、操作用Client Componentを分離した。実ブラウザの一周、全モデルの切替、390px幅の縦配置、取得失敗時の未評価、dialogのEscとフォーカス復帰を確認した。追加のキーボード確認はスライダー名の検索で停止し、ラベルを修正。修正後の追加確認と実機性能、人の試用は未完了。[初回ブラウザ記録](./ai-visual-inspection-browser-validation.md)。確認前の検索公開を避けるため一時的にnoindexとし、sitemap・トップ・ツール一覧への追加はまだ行っていない。デプロイしていない。

## 体験

1. 平坦な面の良品4枚・汚れ2枚で、暗さと面積を調整。
2. 練習用24枚全体（良品12・不良12）で、ルールとAIの検出領域・見逃し・過検出を比較。照明むら補正とAIしきい値も操作可能。
3. 事前学習済み4モデルを切替。実際の学習枚数と、種類・模様・誤ラベルの組合せごとの先頭画像を代表例として表示。
4. 明るさを0.7〜1.3倍に変更。画素そのものを変換し、Workerへ渡して再推論。
5. 設定を固定し、別の24枚で再評価。ルール・AI・OR併用の件数と準備負担を見て採用候補・理由を選ぶ。採点しない。

PCは横並び、640px以下は上下配置。検出領域は実線、正解領域は破線で表示を分ける。Canvasには画像と判定の代替ラベルを付け、一覧の番号・正解・見逃し／過検出・変更記号も文字で表示する。画像一覧から同じ2画像を拡大するnative dialogを開く。Esc・閉じるボタン・操作元へのフォーカス復帰を実装しているが、実ブラウザでの確認は別途必要。

ルール判定は現在の画素・設定で直ちに更新。AIは要求のキーが一致する全件完了結果のみ表示し、操作中・失敗時には「未評価」とする。古い応答や前の設定の件数を現設定の結果として表示しない。しきい値変更はWorker内のスコアキャッシュを使う。確定結果の前回比較は同じ画像集合に限り、変わった画像に△を付ける。

## 画像の選択と比較の意味

`export_lesson.py` が固定ロックを照合してから、開発群の先頭24枚を練習用、既に開封済みの最終群の先頭24枚を確認用へ書き出す。判定結果による並べ替えや画像選別は行っていない。画像・正解マスクは別ファイルとし、`loadLesson` で寸法、ハッシュ、ラベル整合、重複IDを検査する。Workerへ渡すのは画素と設定だけ。

確認用は学習・調整群と分離されているが、開発側では評価済み。利用者に対しても未知データの性能保証とは表示しない。一度開くとページ内のやり直しでも「確認済み」を維持し、設定を変更して再評価する場合も同じ名称とする。永続ストレージは使わず、再読み込みで操作状態は消える。確認画面を開く際は毎回「確認済み」と表示し、再読み込み後も未使用データだとは主張しない。

通常条件・AIしきい値0.5・面積12で、既存のPython参照マスクから数えた練習用24枚の結果は次のとおり。これはUIでの実ブラウザ推論測定ではない。

| モデル | 見逃し／不良12枚 | 過検出／良品12枚 |
|---|---:|---:|
| 広く含む | 0 | 2 |
| 汚れ偏重 | 6 | 0 |
| 良品模様不足 | 0 | 0 |
| 誤ラベル | 0 | 0 |

この小さな部分集合では、模様不足や誤ラベルのモデルの画像判定が良く見える場合がある。全600枚の傾向が24枚でも必ず再現するとは説明しない。学習データを変えると何が変わるかを領域と合わせて比較し、「偏りがあればすべての指標が悪化する」とも断定しない。画像の選び直しで傾向を演出していない。教材として理解が進むかは人の試用で確認する。

## プライバシー・導線

既存のtrackEventで、教材版と固定カテゴリのみ計測。開始・段階完了・モデル切替・明るさ変更・確認・終了・関連リンク・エラーを扱う。画素、判定、しきい値の数値、選択した採用候補・理由、画像ごとの操作履歴は送らない。プライバシーページに端末内処理とメモリ保持を追記した。

終点からGage R&Rへ接続。トップ、ツール一覧、GRR側の逆リンク、検査記事、sitemap、検索公開は実画面確認・人のレビュー後に追加する。需要と競合は引き続き未検証。

- `sync_web.cjs`: 配信アセットのハッシュ・サイズ記録を更新。
