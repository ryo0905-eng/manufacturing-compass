# 半導体職種マップ：検証後のMVP引継ぎ仕様

最終更新日: 2026-09-17
状態: 4職務群のβ版を公開実装。8職務群への拡張は条件付き。

## 着手条件

[手作業検証](./role-map-validation.md)の5人基準、人による根拠レビュー、各Profileの公開基準を満たしてから公開MVPを実装する。現時点の結果は0人、公開判定は未実施。[根拠台帳](./role-map-pilot.md)を完成済みデータセットとして公開しない。

2026-09-17、運営者判断により、4職務群のβ版を `/roles` で公開する方針へ変更した。sitemap、トップ、Career Compassから接続し、回答はReactメモリだけで扱う。開始・結果表示・検索語コピー・関連情報遷移の固定イベントだけを送り、選択業務、候補、検索語は送らない。β版の公開を、5人試用や根拠レビューの完了とは扱わない。

## 提供する体験

- 名称「仕事内容から探す 半導体職種マップ」、URL `/roles`。
- 8職務群：工程改善、生産性改善、歩留まり改善、工場内設備技術・保全、制御・自動化、工程品質、品質保証、顧客先装置立上げ・保守。
- 18業務の選択、特によく担当した業務は任意で最大3件、理由付き候補は最大3件。百分率・適性・採用見込みは表示しない。
- 主操作は日本語・英語の検索語コピー。読み取り専用のコピー対象テキストを常設し、失敗時は手動選択を案内する。
- 職種名・表記揺れを検索できる補助入口。検索0件では全職務一覧と経験選択を案内する。検索文言は保存・計測しない。
- 職務カードに共通業務、名称の使用文脈、担当範囲の違い、検索語、求人票の確認事項、出典・確認日を表示する。
- 最初はハブ内の静的一覧とアンカー。独立詳細ページ・任意2職種比較・求人取得は追加しない。

## データと責務

TypeScriptの静的データを `src/data`、計算・検証を `src/lib`、型を `src/types` に分離する。画面や記事に個別の点数表を重複定義しない。以下は内部データ契約で、外部APIではない。

| 要素 | 必須情報・関係 |
| --- | --- |
| Role | 安定したID、slug、表示名、概要、draft/published |
| RoleProfile | ID、Role ID、半導体領域、事業者種別、担当対象、開発/量産、国内/海外の適用範囲、状態 |
| RoleTitle | ID、名称、言語、同一表記の揺れ。意味の違う名称をaliasだけで統合しない |
| TitleUsage | Title ID、Profile ID、使用文脈、企業例、Evidence ID。多対多 |
| Responsibility | R01〜R18に対応する安定ID、分類、表示名、説明、含む/含まない例 |
| ProfileResponsibility | Profile ID、Responsibility ID、中心/場合あり、Evidence ID群、編集理由。多対多 |
| Evidence | ID、URL、資料名、発行者、企業グループID、確認日、資料内更新日（不明なら未設定）、適用範囲、短い要約、利用条件確認状況、次回確認日、active/withdrawn |
| SearchPhrase | ID、Profile ID、日本語/英語の検索語案、確認事項、根拠となるTitleUsageまたは業務。編集提案と明示 |
| RoleRelation | 関連Role ID、共通業務、異なる担当範囲、Evidence ID、編集理由 |
| Review | Profile ID、レビュー状態・確認者・日付、根拠ゲートの結果。未レビューはpublished不可 |

道具・手法・能力の補助情報は種類を分け、結果の説明にだけ使う。経験年数・英語・年収・希望条件を類似度へ混ぜない。既存Career Compassの職種文字列、国内拠点のJobFamilyとは明示的な対応表で結ぶ。粗い分類への対応を、その企業の募集職種の根拠にしない。

公開データは2社以上・3資料以上、中心業務に2社以上の支持、人による確認、利用条件確認を満たすものだけ。求人転載や翻訳転載を別資料として水増ししない。draftは公開画面・候補・構造化データから除外する。根拠を失ったProfileも候補から外す。

## 候補抽出と状態

計算は手作業検証と同じ重み付き一致を純粋関数で実装する。入力は選択業務IDと強調業務IDのみ。戻り値はProfile ID、共通業務ID、同程度の候補であること、内部並べ替え値。内部値を表示コンポーネントや計測へ渡す必要はない。

- 未知IDと重複を除去し、強調IDは選択済みに限定、最大3件。通常UIでは4件目を選べない。
- 選択変更で強調の不整合を除去し、旧結果・コピー成功表示を破棄する。「候補を見る」で再計算する。
- 一致業務2件以上、中心業務1件以上を通常候補の条件とする。同一職務群は最も一致するProfileだけを採用する。
- 同点は順位差を示さず、安定ID順で表示する。最大3件。該当0件を一般候補で埋めない。
- 入力0件・1件・対象外は適切な説明と入力へ戻る操作を出す。一般業務だけで分類を断定しない。
- 未選択・未確認は能力不足や業務不存在の証拠として扱わない。

状態はReactメモリだけ。URL・Cookie・localStorage・外部APIへ回答を保存/送信しない。再読み込みで消去。クリップボードは本人のボタン操作時だけ書き込む。

## UI・導線・SEO・計測

Server Componentが説明、職務一覧、名称例、出典、更新日を初期HTMLへ出力し、Client Componentが選択・候補・検索・コピーを担当する。両者は同じ公開済みデータを参照する。

スマホは一列。業務はグループ別のcheckbox、強調は選択済み項目から選ぶ。ラベル・フォーカス・選択件数を明確にし、結果とコピー状態を読み上げ可能にする。結果表示時だけ見出しへフォーカス移動し、入力ごとの自動スクロールはしない。

公開時にCareer Compass入口・結果、関連する生産技術/設備/品質記事、企業のキャリア準備から接続する。ヘッダーの既存Career Compass CTAは「経験と次の準備を整理する」へ変更。ナビ項目追加はしない。結果は検索語コピーを主操作にし、Career Compass・企業研究・相談準備を補助にする。

`/roles`だけをcanonical・sitemapへ追加。WebPage、BreadcrumbList、一覧にItemListを使用し、表示本文と一致させる。JobPostingは使用しない。結果や入力のURL化、表記揺れページ、比較全組み合わせの生成はしない。

既存Analytics経路に次の固定イベントを追加する。パラメータは付けず、初期表示や再レンダリングで重複送信しない。

| イベント | 発火 |
| --- | --- |
| role_map_start | 初めて業務を選択した時に画面の利用中1回 |
| role_map_result_view | 「候補を見る」で結果を出した時。二重クリックを防ぐ |
| role_map_search_copy | 明示コピーが成功した時だけ |
| role_map_related_click | 関連情報リンクを明示的に押した時 |

回答、強調業務、候補ID、得点、検索語、クリップボード本文を送信しない。手動コピー成功を自動計測したことにしない。

## 検証と公開判定

計算の単体確認は、空入力・1件・一致なし・一般業務のみ・重複/未知ID・強調上限・選択解除・同点・複数Profileの非合成・最大3件を対象とする。理由と選択の一致、根拠ゲート、参照切れ、draft除外も確認する。

UIはコピー成功/失敗、入力変更後の結果破棄、キーボード操作、スマホ一列、静的本文、送信パラメータなしを確認する。リポジトリの実行方針を守り、typecheck最大1回、build・ブラウザ確認はユーザーの依頼条件に従う。未実施の確認は記録する。

公開前の試用10人で、8人以上が補助なしで検索語を取得、7人以上が上位3候補に業務上の接点を認めることを目標にする。誤解は修正版で再確認する。公開後は開始・結果・コピー・遷移を代理指標として追い、求人発見の価値は同意を得た試用で確認する。

本番反映、Analytics受信、SEO結果はローカル実装と別に記録する。commit・push・デプロイは個別の明示依頼がない限り行わない。
