## 修正

`getByLabel('採用候補', { exact: true })` が要素を取得できなかった。既存のマークアップではselectと全optionをlabel内に含めていたため、選択肢を含まない一意のラベルに整理した。採用候補、重視したこと、モデル切替、画像一覧それぞれに明示的な `htmlFor` と `id` を設定した。実画面の選択操作自体が不可能だったとまでは判断していない。

PC画像ではチェックボックスと説明が上下に離れていた。該当ラベルだけをinline-flexにして、サイト共通のフォーム表示に引っ張られないようにした。色・判定ロジックは変更していない。

対象UIテストに、ラベルの一意な対応、ラベル文字列への選択肢の混入防止、採用候補・理由を選んで振り返りを終える操作を追加。Nodeのフック用ハーネス・SSRで通過した。型チェックも1回通過。修正後の実ブラウザ再確認は未実施。

## 次回の確認

リポジトリの「停止・失敗した検証を、別設定、一時tsconfig、類似コマンドで繰り返さない」という実行方針に従い、このターンでブラウザの再実行はしていない。

同じ操作を再現できる `scripts/ai-visual-inspection/check_browser.cjs` を追加した。Node 22で実行し、開発サーバーを起動して終了時に停止する。進捗と失敗情報を終了時に保存するよう改善し、次回は欠陥画像と正解領域の撮影、Worker内リソースの通信記録も行う。追加したランナーは構文チェックのみ実施し、まだ実行していない。

ブラウザ確認では通常環境の一周に加え、残るモデルの切替、フィルター、連続操作、キーボード、スマホ相当画面、取得失敗時を確認する。開発サーバーの転送量やデスクトップの処理時間は、本番の圧縮転送量・スマホ実機性能と分けて記録する。

browser-actは1.4.2の存在を確認したが、手順取得時にアプリケーションのログ保存先への権限エラーで停止した。既存依存のPlaywrightで上記確認を実施した。browser-actの設定やインストールは変更していない。

noindexと公開導線の保留を維持する。人による画像・文面レビューと製造経験者3人の試用も未完了。
