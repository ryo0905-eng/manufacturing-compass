## 測定できた範囲

明るさを0.7倍へ変更してから24枚の更新完了まで **1,421ms**。入力操作・待機・描画・推論を含む1回の測定で、推論だけの時間ではない。このPCの開発環境での値をスマホ性能や安定した上限として扱わない。

WorkerのResource Timingから、初回のORT JS・manifest・基準モデル・WASMローダー・WASMの5件を取得。encodedBodySize合計は **3,380,498 bytes（約3.38 MB）**、transferSize合計は3,381,998 bytes。WASM本体は圧縮後2,878,594 bytes、展開後11,210,254 bytes。モデルは477,448 bytesで、この環境では未圧縮だった。

この測定はUIバンドルとWorker起動モジュールを含まない。アプリ全体の初回追加転送15MB目標を確認済みとはしない。本番の圧縮・キャッシュ条件やスマホ実機の選択画像500ms、24枚3秒の目標は別途測定が必要。

## 修正と履歴

初回の一周は `getByLabel('採用候補', { exact: true })` が取得できず停止した。selectと全optionをlabel内に含めていた構造を整理し、採用候補、理由、モデル、画像一覧へ明示的なlabel/idを付けた。チェックボックスと説明の改行も修正した。今回の一周で振り返り終了まで通過し、チェックボックスの表示も確認した。

今回の追加確認は `getByRole('slider', { name: 'AIの欠陥らしさのしきい値', exact: true })` の検索で停止。Controlの一つのlabel内にrangeとnumberの2入力を含めていたため、range専用のlabelをuseIdで対応付け、数値入力は独立したaria-labelで識別する形に変更した。判定や値の更新処理は変更していない。

修正後のUIテストで、2つのControlのIDが重複しないこと、ラベル文字列が入力値を含まないこと、rangeのlabel/idと数値入力の名前を確認。既存の状態遷移・SSRテストと型チェック1回が通過した。ブラウザでのスライダー再確認はまだ行っていない。
